# Research: Critical Missing GNU Options

Source: DOCS/generated/gnu_option_gap_audit.md, generated by comparing GNU coreutils 9.4 help output with WinuxCmd OPTION declarations. The complete lists below reproduce the audit. “Common in scripts” is a practical compatibility judgment, not telemetry. P0 is critical compatibility/data-integrity behavior, P1 is broadly useful, and P2 is niche or presentation-oriented.

## Cross-command guidance

Implement behavior families with shared parsers for binary and NUL-safe I/O, file operands, quoting, color, time selection, numeric sizes, and glob matching. Accept an option only when behavior is implemented; otherwise emit a clear unsupported-feature diagnostic rather than silently changing results. Add GNU 9.4 golden tests for stdout, stderr, exit status, encoding, and filesystem side effects.

## 1. patch

### Complete audited missing list

--backup, --backup-if-mismatch, --basename-prefix, --batch, --binary, --context, --directory, --dry-run, --ed, --force, --fuzz, --get, --ifdef, --ignore-whitespace, --input, --merge, --no-backup-if-mismatch, --normal, --output, --posix, --prefix, --quiet, --quoting-style, --read-only, --reject-file, --reject-format, --remove-empty-files, --set-time, --set-utc, --silent, --strip, --suffix, --unified, --verbose, --version-control, -B, -D, -E, -F, -T, -V, -Y, -Z, -c, -d, -e, -f, -g, -l, -n, -o, -r, -s, -t, -u, -v, -z.

### Priority and script prevalence

P0: --dry-run/-t for CI previews; --directory/-d; --input/-i and --output/-o; --fuzz/-F; --ignore-whitespace/-l; --force/-f; --backup/-b and --suffix/-V; --reject-file/-r; --remove-empty-files/-Z; --binary/-p; --set-time/-T. These are the options most likely to affect unattended patch application and data safety.

P1: --backup-if-mismatch, --no-backup-if-mismatch, --basename-prefix, --context/-c, --unified/-u, --normal/-n, --ifdef/-D, --merge, --read-only, --quiet/--silent/-s, --verbose/-v, --strip, --prefix, --reject-format, --version-control, --set-utc, --posix.

P2: --ed/-e, --get/-g, -E, -Y, -z, and --quoting-style. These are legacy, transport-specific, or mainly diagnostic/output controls. Verify short-option argument arity against GNU 9.4 before coding because the audit lists declarations without arity.

### Windows-specific challenges

Open patch streams in binary mode to preserve CRLF/LF and binary bytes. Rename/backup can fail for open files, read-only attributes, ACLs, or sharing violations. Drive letters, UNC paths, case-insensitive lookup, symlinks, junctions, and reparse points complicate directory, prefix, strip, and traversal checks. Unix modes, ownership, and timestamps do not map fully to NTFS/ACL semantics. --ed and RCS-style --get require external-tool integration or an explicit unsupported result.

## 2. diff

### Complete audited missing list

--color, --from-file, --horizon-lines, --ignore-file-name-case, --label, --left-column, --line-format, --no-dereference, --no-ignore-file-name-case, --normal, --palette, --speed-large-files, --strip-trailing-cr, --suppress-blank-empty, --suppress-common-lines, --tabsize, --to-file, --unidirectional-new-file, -D, -E, -F, -I, -N, -S, -T, -W, -X, -Z, -a, -b, -d, -e, -i, -l, -n, -p, -r, -s, -t, -v, -x.

### Priority and script prevalence

P0: -r for recursive trees; -N/--unidirectional-new-file; -a; -b and -E; -i; --strip-trailing-cr; -I; --from-file and --to-file; --label. These dominate generated-tree, source-control, CI, and cross-platform comparisons. WinuxCmd already has extra equivalents for all-space, blank-line, unified, context, side-by-side, and brief modes; reuse their implementations where semantics match.

P1: --color, --suppress-common-lines, -x and -X, -S, filename-case toggles, --normal, --suppress-blank-empty, --line-format, -D, -F, -p, -T, -l, -n, and --tabsize.

P2: --horizon-lines, --left-column, --palette, --speed-large-files, --no-dereference, -d, -e, -t, -v, and -Z; these are tuning, pager, or niche presentation features.

### Windows-specific challenges

CRLF normalization, UTF-16/BOM decoding, and byte-vs-text comparison must be explicit. Color needs virtual-terminal detection and should be disabled for redirected output. NTFS case-insensitivity affects filename-case options; symlink/junction traversal needs a reparse-point policy. Large trees require streaming and bounded memory. Drive-letter colons must not be confused with GNU label syntax.

## 3. ls

### Complete audited missing list

--author, --block-size, --color, --dereference-command-line-symlink-to-dir, --file-type, --format, --full-time, --group-directories-first, --hide, --hyperlink, --indicator-style, --quoting-style, --show-control-chars, --si, --sort, --time, --time-style, --zero, -h, -u.

### Priority and script prevalence

P0: -h; --sort and --time/-u; --format for one-per-line or stable output; --quoting-style and --show-control-chars; --file-type/--indicator-style; --color=never; and --zero for robust pipelines. Stable names and ordering matter more than terminal cosmetics.

P1: --block-size, --si, --full-time, --group-directories-first, --hide, --author, --time-style, --dereference-command-line-symlink-to-dir, and --color=auto|always.

P2: --hyperlink and uncommon indicator, quoting, and control-character combinations. Hyperlinks should be capability-detected and suppressed when redirected.

### Windows-specific challenges

Owner/group, author, inode, device, SELinux context, and Unix permissions lack direct Windows equivalents; retain existing WinuxCmd conventions and document unavailable fields. Reparse points include symlinks and junctions. Creation/write/access timestamps differ from GNU assumptions. Unicode names, surrogate pairs, reserved names, case-insensitive sorting, console width, color, OSC-8 hyperlinks, and NUL-safe redirected output all require dedicated tests.

## 4. grep

### Complete audited missing list

--binary-files, --color, --colour, --exclude, --exclude-dir, --exclude-from, --group-separator, --include, --label, --line-buffered, --no-group-separator, --no-ignore-case, -V, -h.

### Priority and script prevalence

P0: --include, --exclude, --exclude-dir, and --exclude-from for source/build searches; --binary-files; --color=never|auto|always and the --colour alias; -h; --no-ignore-case; and --line-buffered. These are routine in CI, log processing, and recursive searches.

P1: --group-separator, --no-group-separator, --label, and -V. --colour should be a spelling alias, not separate behavior.

P2: none functionally; after P0/P1, focus on exact diagnostics and edge-case parity.

### Windows-specific challenges

Binary detection must inspect bytes, not decoded strings. CRLF affects line boundaries and offsets. Color must account for redirected handles and virtual-terminal support. Include/exclude needs GNU glob semantics across drive, UNC, backslash, case-insensitive, and reparse-point paths. --line-buffered requires explicit flushing and may be costly. Regex case behavior must remain independent of filesystem case.

## 5. numfmt

### Complete audited missing list

--debug, --field, --from, --from-unit, --grouping, --header, --invalid, --padding, --round, --suffix, --to, --to-unit, -M, -z.

### Priority and script prevalence

P0: --from/--to; --from-unit/--to-unit; --field; --invalid; --round; and -z. These define conversion correctness, column selection, malformed-input behavior, deterministic rounding, and robust NUL-delimited pipelines. Share strict numeric parsing and overflow checks.

P1: --header, --suffix, --padding, --grouping, and -M. These are common for tabular reports and human-facing output, but should follow core conversion and error semantics.

P2: --debug, which is diagnostic.

### Windows-specific challenges

Windows regional settings must not make CI grouping or decimal output nondeterministic; use explicit locale policy. Binary streams are required for -z and NUL/newline handling. Unicode suffixes and localized digits need explicit encoding. Large integers must avoid platform-dependent width and overflow. Define GNU-compatible invalid-input diagnostics and exit statuses for redirected handles.

## Suggested delivery sequence

1. Shared infrastructure: option arity/aliases, binary and NUL-safe I/O, deterministic locale/encoding, path/glob matching, and a GNU 9.4 golden-test harness.
2. P0: grep filters/binary/color; diff recursive/text/CRLF controls; ls stable format/sort/time/quoting; numfmt conversion/invalid/rounding; patch dry-run, directory, input/output, fuzz, whitespace, backup, and reject behavior.
3. P1: headers, labels, alternate formats, presentation, and platform-aware metadata.
4. P2: hyperlinks, pagers, tuning flags, and external-tool-dependent patch modes.

The audit is option-surface based. Validate every short alias and argument-taking form against GNU 9.4 help before implementation, especially patch -p, -r, -t, and -T.
